# ADR 0003：Linux 宿主集成——无 COM 环境下的公式对象编辑

日期：2026-10-12 · 状态：已接受

## 背景

ADR 0002 确定「嵌入对象服务器（OLE）为主机制」。实测（#15，strace 级证据）表明
WPS Linux **没有 COM/OLE 宿主能力**：无 SCM、无类注册机制、双击对象时 execve
计数不变——宿主根本不会尝试激活第三方服务器。这是闭源宿主的既成事实，不是我们
一侧可修的缺陷。

## 决策

在 Linux 宿主上放弃进程内 OLE 激活路径，改用**两层替代架构**：

1. **文件级编辑**（转换桥）：加载项把文档路径与对象序号交给桥；桥用 mt-docx 直接
   读写 docx 部件（对象流、预览图、形状尺寸），全程不经过宿主的文档写入器。
   WPS 自身的保存/另存会全量重写文档并破坏 MathType 对象（实测丢部件），因此
   流程中**绝不调用宿主的 Save**；关闭重开是必要环节（无进程内通道）。
2. **事件级激活模拟**（加载项）：注册 WindowBeforeDoubleClick / WindowSelectionChange
   （按宿主版本可用性防御式注册）+「编辑公式」按钮兜底，把"双击进编辑器"的体验
   拼回来。

对象格式双向互认：读与写都覆盖 MathType 的 `Equation.DSMT4` 与我们的
`MathTypeRs.Equation.1`（同一 MTEF 流），插入的新对象默认即 MathType 格式
（#34/#36），与 MathType 用户协作无需转换。

## 后果

- Linux 上「文档重开」不可避免；滚动位置丢失是已知代价。
- Windows 宿主仍走 ADR 0002 的 COM 服务器路径（#19 排查中）。
- 剪贴板互通（#9/#12）不受本决策影响，属宿主无关通道。
